Application Architecture

End-to-end map of Spolysis: phone recording → signed upload to R2 → Temporal orchestration → Modal GPU analysis → results back in the app.

Phase 1 free tier — code shipped Phase 2–3 premium 3D — designed

1. What this system does

Amateur players film a stroke. The system finds the body, classifies the stroke/fault (free), or reconstructs 3D motion and shows a corrected skeleton on their footage (premium).

Free (2D)

  • RTMPose-x skeleton per frame
  • ST-GCN → stroke + fault
  • Claude phrases rule-based coaching
  • Curated pro clip lookup (not generated)

Premium (3D)

  • Lift 2D → 3D (MotionBERT / PoseMamba)
  • DTW align vs pro reference
  • CCD IK on user’s own bone lengths
  • Overlay video + Three.js viewer

3. User journey (simplified)

What happens from “Record” to “Results,” layer by layer.

Phone — frame & record Body outline + ML Kit: full body, side-on, distance OK → record (max 5 min)
API — job + signed URL Create job in Supabase, mint R2 presigned PUT, start Temporal workflow
R2 — store video App uploads bytes directly to raw/<job_id>/video.mp4 (API never holds the file)
Temporal + Modal — analyze ffmpeg frames → quality gate → RTMPose → free or premium branch
App — results Poll/push → text + pro clip (free) or overlay + 3D viewer (premium)

6. Free vs Premium branches

Important: ST-GCN output does not feed the 3D lifter. Both branches start from RTMPose keypoints. Each node below shows the full name and what it does.

Free — Phase 1 (shipped)

Feature extraction — turn keypoints into joint angles, velocities, normalized positions
Stroke segmentation — find the swing window using wrist speed peaks
ST-GCN — Spatio-Temporal Graph Convolutional Network: classify stroke + fault from skeleton motion
R2 clip lookup — Cloudflare R2: fetch curated pro reference video by stroke/fault
Rules + Claude — rules pick findings; Claude API only rephrases into coaching text
App result — show text recommendation + pro clip

Premium — Phase 2–3 (designed)

MotionBERT / PoseMamba — neural 3D pose lifters: 2D skeleton sequence → 3D joints over time
Savitzky-Golay → SmoothNet — filter then motion-aware network: remove jitter from 3D path
Normalize + phase detect — root-center/bone normalize; split prep → backswing → contact → follow-through
Keyframe-anchored DTW — Dynamic Time Warping: align user vs pro motion despite different speeds
CCD IK — Cyclic Coordinate Descent Inverse Kinematics: bend user’s joints toward pro angles
OpenCV + ffmpeg + Three.js — draw overlay, encode H.264 video, interactive 3D viewer

Glossary — every tech in this diagram

Name Full form What it does here
RTMPose-x Real-Time Multi-person Pose (extra-large / max-accuracy variant), via MMPose Finds 17 body joints on every frame as 2D (x, y, confidence). Shared input for both branches.
Feature extraction — Converts raw keypoints into biomechanics-style numbers: joint angles, velocities, normalized positions for classification.
Stroke segmentation Heuristic wrist-speed peak detection Finds where the swing starts/ends in the video by looking for a spike in wrist velocity (contact / swing).
ST-GCN Spatio-Temporal Graph Convolutional Network Treats the skeleton as a graph (joints + bones) over time; outputs stroke type (e.g. serve) and fault label (e.g. arm_only). Learns from labeled examples, not built-in tennis knowledge.
R2 lookup Cloudflare R2 (object storage) Looks up a pre-uploaded pro teaching clip by stroke/fault key. Not AI video generation.
Rules + Claude Rule thresholds + Anthropic Claude API Code decides what is wrong from metrics/labels; Claude only rewrites that into natural coaching language.
MotionBERT Motion Bidirectional Encoder Representations from Transformers (human motion model) Candidate 3D lifter: takes a sequence of 2D poses and predicts 3D joint positions over time (fast regression, not slow optimization).
PoseMamba Pose estimation model using Mamba (state-space sequence model) Other 3D-lift candidate; same job as MotionBERT. Both fine-tuned on tennis; winner ships.
Savitzky-Golay Savitzky–Golay filter (SciPy) First smoothing pass: removes gross noise/jitter from the 3D joint paths while keeping the overall shape of the motion.
SmoothNet SmoothNet (learned human-motion temporal smoother) Second pass: understands human motion structure; produces cleaner trajectories so the overlay doesn’t look broken.
Skeleton normalization — Root-centers the body and normalizes bone lengths so comparison isn’t “you’re taller than the pro.”
Phase detection — Labels stroke phases: preparation, backswing, contact, follow-through — so deltas are reported per phase.
DTW Dynamic Time Warping (keyframe-anchored; Sakoe–Chiba band) Stretches/compresses time to align your swing to the pro’s even if speeds differ; locked at contact (wrist velocity peak).
Biomechanical deltas — Numeric gaps vs pro, e.g. “hip rotation at contact: you 34°, pro 52°.” Phase 2 validates these before rendering.
CCD IK Cyclic Coordinate Descent Inverse Kinematics Adjusts only flawed joints in the flawed time window toward target angles, preserving your bone lengths (never pastes the pro’s body).
OpenCV Open Source Computer Vision Library Projects the corrected 3D skeleton back onto the original video frames as a distinct overlay.
ffmpeg Fast Forward Moving Picture Experts Group (media toolkit) Encodes the overlaid frames into an H.264 result video for the app/CDN.
Three.js Three.js (WebGL 3D library for the browser) Interactive premium viewer in the app: rotate and scrub the corrected 3D skeleton.
